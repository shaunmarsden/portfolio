A high score can hide the wrong failure.

A repeated model evaluation that kept critical misses visible, then tested deterministic controls.

The problem

A service-information router can produce valid JSON and a plausible answer while missing a consequential escalation. Aggregate accuracy alone is a poor acceptance criterion.

Architecture & approach

  1. Fictional enquiry
  2. Stateless provider interface
  3. Schema + routing scorer
  4. Guard + source contract

Use 32 main and 16 holdout cases, each repeated three times, alongside a transparent keyword baseline. Record model settings, response status, token usage and scoring. Later offline comparisons applied a deterministic escalation guard and source constraint, with separate development and frozen holdout inputs.

What was actually tested

The authorised 21 October evaluation made 144 calls over 48 authored cases, not 144 independent examples. Two false escalations also occurred. The later guard-repair holdout improved 15/30 to 30/30, with critical misses 5 → 0 and false escalations 10 → 0. It was agent-authored, not independently labelled. The full lab has 119 automated tests.

A failure that changed the design

The original model missed urgent cancellation and safety-related hand-offs despite successful HTTP responses. Later controls also exposed false escalation on quoted examples and reminders. The bounded repair added context-sensitive handling without rewriting the original results.

  2. Acceptance check

    Inspect the escalation decision and consequence, not just JSON validity.

The limit of the result

The scorer checks routing, schema and allowed source IDs, not free-text truth. Historical deterministic replay still has nine routing errors; the combined saved-model guard/source replay has 13. The 24-response AI-assisted critique is not independent validation. Original raw replies and review mappings remain private. No fresh model-control effectiveness, usability or review-time result is claimed.

Keep consequential error severity separate from overall accuracy. The evidence supports cautious evaluation and explicit stop rules, not autonomous public guidance or a claim that a later 30/30 diagnostic solved the general problem.

Contribution & validation

I authorised the spend and ran the original live evaluation from my Terminal. Code, offline regression work, later guard analysis and the review cross-check were Codex-assisted. A separate ChatGPT review assessed 24 selected responses; it was AI-assisted critique. Independent human validation: not performed, not pending for this closed phase.

What the work demonstrates

Evaluation design, provider boundaries, meaningful baselines, severity-based acceptance and disciplined interpretation of model results.

Workplace use would require representative authorised data, accountable owners, authenticated identities, security and operational review, and evidence of actual workflow value. None is claimed here.
